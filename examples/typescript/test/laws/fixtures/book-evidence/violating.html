EXERCISED VERSUS SPECIFIED-BUT-UNPROVEN

The fourth column above is not decoration; it is the difference between a specification and a demonstration, and a reference that blurs the two is asking for trust it has not earned. Every rung in the ladder is now exercised by the accompanying ports, on the terms stated — which is why the rungs were built at all: so the reference runs what it prescribes. 16.4 still holds and is unaffected: exercising a rung here is not an argument that your app should take it.

What is specified but unproven is worth naming precisely, so nobody reads parity where there is none. The replay tooling beyond a re-fold — an interactive scrubber UI, a fork-from-step, an interactive diff — is described, not shipped; what ships is the re-fold itself, the prefix re-fold at step k a scrubber is built on, the effect-sequence comparison, and the per-step context-digest check. Schema evolution (14.7) ships one rung in the ports and no more: every record carries a required schemaVersion, and one worked v1→v2 upcaster lifts a payload that gained an optional field, with the old record refused by the type system rather than by a runtime branch — in both halves, the envelope and the historical payload. What is untested ground is the rest — an upcaster chain, a versioned wire encoding (14.1 leaves that product-owned), a golden trace pinned per reducer version, and any dispatch on the version at load time: these ports read the envelope at COMPILE time and never at run time, because they deliberately ship no loader to read it in. The hard swaps of 8.5 — a sharded or networked bus, a durable persistence and retention strategy, snapshotting for very long sessions, multi-tenant isolation — are contracts with in-memory adapters behind them; the seam is proven, the distributed implementation is not, and 8.5's own qualifier applies (one adapter prices the integration, not the algorithm). Cross-session budgets (17.1) are named as a product-owned seam and left there. And one structural claim deserves its own line, because it is the sort that quietly degrades in an adopter's hands: the single-dispatcher confinement of a turn's submit channel is structural in the reference and not gate-checkable. The consumer mints the channel and calls the boundary itself, so the reference cannot violate it — but an adopter who runs a turn on another thread and folds from there can interleave two folds despite every rule above. No check catches that; only the shape does.
