Seam 07 · The payoff, and more boundaries

Replay and the advanced seams.

The cash value of every seam before it. Because the bus is append-only and the fold is pure, you run a session for real and then re-derive it from its own committed records — the same State, the same effect sequence, every timestamp and every key — with no model, no network, no clock, no surface. This is the outermost circle: the test that proves every other seam held.

▸

The seam at a glance

The eight slots, the same shape as every other seam — the last time you read them. This is where seams 01–06 get cashed.

The seam
The harness that proves every other seam holds. Its job: re-derive the whole session from the committed records alone, and show that what it derives is what the live run actually did.
Each side
Inner: refold over the committed records — pure, the same fold the live path runs. Outer: the bus — a file, not a world — and, held against it, the state and the effects a real boundary produced.
What crosses
In: the committed StepRecords — the schemaVersion envelope, now, the Signature, the staged input, the actions asked, the results folded, the signed commands, the context digest. Out: a State and a full KeyedEffect sequence, compared against the live ones. Forbidden: re-hitting a live source on re-fold — a tool result that depends on the world must be a recorded fixture, never recomputed.
Direction
All dependency points inward at the fold; nothing points out to a clock, a model, or a sink. There is no control flowing outward here at all — REPLAY mode performs nothing on the world.
The inversion
The fake port sits behind the domain port: where the live root wired HttpModel and a real pager, the harness wires a scripted model and recording sinks — and on the re-fold, no clock at all, because now comes off the record. The core cannot tell — it was always handed values, never a world.
Why it exists
Replay is the concrete payoff of purity: debugging is replay, there is no hidden mutable state to reproduce, and a regression is a stored stream that re-folds wrong. Every prior seam exists so this one can.
What breaks
Anything that leaves the recording incomplete. If the fold read the clock instead of taking now off the record, if the boundary committed the pair and not the step, if a block opened a second bus — the re-fold and the live run disagree, and this is where you find out.
The test
Drive a real session; keep the State and the performed KeyedEffects. Then refold(initial, bus.records()) and assert both match — the full sequence, keys and timestamps. Then collectPerform(…, mode = REPLAY) and assert the same descriptors come back while the pager, the delivery and the log stay empty. (refold is just the step-level fold run over the committed timeline.)
A

What it is

Clean Architecture's last word on the rings is a quiet one: tests are the outermost circle. They depend inward on everything and nothing depends on them, so they are free to be ruthless. This architecture takes that literally and hands you the sharpest possible instance of it. The whole session was committed to an append-only bus at the boundary — one StepRecord per step, carrying the now the boundary read, the Signature it stamped, the staged input, the actions that were asked for, the results that were folded, the signed commands, and the digest of the context the reasoner saw. That recording is everything you need to re-derive the run. So the test is short, and it is an equation between two runs of the same session — one live, one from the bytes:

the replay harness — verbatim from the assembled programpseudocode
replayTest(app, initial):              // a LIVE run, then a replay of its own bytes
  drive(app, [ setPriority, requestEscalation, confirmEscalation(self),
               confirmEscalation(a different authority), recordFinding,
               requestSeal, confirmSeal ])          // one real session, moving clock

  liveState   = app.boundary.state
  liveEffects = app.sink.performed         // [KeyedEffect] — keys AND every `at`

  (state, effects) = refold(initial, app.bus.records())   // the COMMITTED BYTES, only
  assert state   == liveState                             // what the run believed
  assert effects == liveEffects                           // the FULL sequence, in order

  replaySink = RecordingSink()
  collectPerform(initial, app.bus.records(), replaySink, mode = REPLAY)
  assert replaySink.performed == liveEffects              // descriptors collected …
  assert world.pages == [] and world.deliveries == []     // … and NOTHING fired

Ten lines, and there is no model in them, no network, no clock of their own, no surface — but there is a live run, and that is the whole of the fix. refold threads the recorded results through the same pure fold the live path runs, taking each step's now off the record where the boundary committed it, and keying each effect by the committed step index — so what it produces is not an approximation of the run, it is the run. Then it compares: the state the re-fold derives against the state the live boundary actually held, and the effects it derives against the effects the live sink actually performed, the whole sequence, keys and timestamps included. Finally collectPerform drives those same effects through the perform seam in REPLAY mode, which collects every descriptor and touches nothing: the same list comes back, and the pager, the delivery and the log are all still empty. That is the entire payoff of every earlier seam, made executable.

B

What crosses it — recorded data, never a live world

Exactly one thing crosses into the harness: the committed records. They are plain data — one StepRecord per step, the same value the boundary appended at commit time on page 02. The one worth naming is now: the commit is the step, not the command-and-result pair, because a re-fold that cannot read the clock the live run read reproduces a different state and calls it agreement. (This reference committed the pair and lost every timestamp — live at:1001 came back as at:0 — which is precisely the kind of thing a fold-against-itself test cannot notice.) Nothing else may cross. The forbidden payload here is not an entity or a live handle; it is subtler and more tempting: re-hitting a live source on re-fold.

The rule is a single sentence. A tool result that depends on the world must be a recorded fixture, not recomputed. If focusTicket enriched its FocusTicket result by querying a live index the first time, replay must read the captured result back from the record — it must not re-run the query. The fold never sees the difference, because the fold only ever consumed ToolResult data; whether that data came from a live tool or from the recording is a fact about the outer ring, settled at composition. This is the same inversion as seam 05, one notch deeper: where the root swapped HttpModel for ScriptedModel, replay swaps the entire sensing-and-tool surface for a recording, and the pure core is none the wiser.

Why “commit before perform” is what makes this possible

Recall the boundary's fixed order: commit, then perform — and notice that it is not a convention you could reverse by accident. Every effect crosses the perform seam wrapped in its key, and the key is (committed step index, index within the step); the step index does not exist until bus.append has returned it. Perform cannot run before the commit, because it has nothing to call with. So the recording is a complete and faithful account of every decision — including ones whose live effects later failed. Replay folds that account and performs nothing; it does not need the effects to have happened, only to have been recorded as intended. (Dedup-on-key belongs to recovery, the third mode: re-drive a committed timeline through a sink that dedupes on that same key and the same confirm pages on-call exactly once, however many times the crash-restart runs it. Replay performs nothing, so it has nothing to dedupe.) The append-only bus is not a log you keep for forensics; it is the input to the test.

C

Why replay is the whole point

Most architectures earn testability seam by seam and then test against a thicket of doubles: a fake clock here, a stub gateway there, a recording sink somewhere else, each standing in for a piece of the world the code reaches out to touch. This architecture spent six seams pushing every reach-for-the-world into one auditable place so that the test at the end needs none of that scaffolding. The clock was injected, so the recorded now reproduces time. Identity was minted at one seam, so the recorded ids are the ids. Effects are descriptors, so REPLAY mode collects them without firing them. And the fold is pure, so it is a mathematical function of (initial, records).

That last property needs stating carefully, because it is exactly what the earlier version of this harness got wrong. If the fold is a function, then folding the same array twice and asserting the two results match is true by definition — the assertion cannot fail, so it is not a test. This reference shipped that test for a long time, and measurement was unkind to it: the impurity § D describes was injected into a tool, the world was mutated between the two folds, and the harness stayed green with the tool's side-effect count unmoved — because folding recorded results never invokes a tool at all. Purity is what makes replay possible; it is not something replay can check. What the harness checks is the one thing purity does not hand you for free: that the bytes the boundary committed are sufficient to re-derive the run that actually happened. That is why the equation has a live run on one side of it.

That is why the payoff is stated as debugging is replay. A production incident is not a mystery to be reconstructed from logs and intuition; it is a recorded stream you fold on your laptop, deterministically, until the line that misbehaves reveals itself. A regression test is not a hand-built fixture; it is yesterday's stream, asserted to still re-fold to the same State. There is no hidden mutable state to reproduce, because the architecture forbade hidden mutable state at every seam that came before. Replay is not a feature bolted on at the end — it is the shadow that purity casts.

What replay does and does not buy

Be exact about the guarantee, because the cumulative impression of a page like this one is easy to overstate. What you get is determinism over a recorded timeline: the run that was recorded re-derives exactly, bit for bit, from its own committed bytes — which is what makes forensics, audit, and yesterday's production trace as a regression fixture real. What you do not get is behavioural reproducibility. Re-running the model is not deterministic and this architecture never claimed it was; an input that was conflated away mid-turn was never recorded, so it cannot be replayed — though the shedding is: a busy-drop folds a counted, signed command before the winning turn starts, so the record says load was shed and how much, even where the shed body is gone. Replay is not a promise that the agent would decide the same thing again. It is a promise that what it did decide is recoverable, in full, from the record — including the parts nobody thought to log.

D

What breaks without it

This seam is unusual: it has no “collapsed version of itself” to show, because the failure is never here. The harness is ten lines; there is nothing in it to get wrong. What it can fail on is a leak in an earlier seam — but it is worth being precise about which leaks land here and which do not, because this page used to be wrong about exactly that, and the wrong version is the more comfortable story. Here is the most common temptation, the one seam 02 warned against:

Collapsed — a tool reads the world instead of returning a fixture

VERB focusTicket = Reversible {
  input = { ticket: TicketId }
  run(input, ctx) -> FocusTicket(input.ticket,
    known: liveIndex.query(input.ticket))  // reads the world, not ctx
}

It looks harmless — it just answers truthfully from the freshest source. But known is now a function of the live index rather than of the tool's input and the committed State, so what the recording holds is no longer reproducible from the recording. And the test that dies is not this one. Say it plainly, because an earlier version of this page said the opposite: replayTest re-folds committed results and never invokes a tool body at all, so a tool reading a mutable global sails straight through it. That was measured against this very reference — the violation above was injected, the world was mutated between runs, the harness passed, and the tool's side-effect count never moved. The check that dies is a build check: the blocking rule that a block's pure files may not import a runtime module, may not read a clock, may not reach the network (§ E below). It fails the moment the line is written, in the build, naming the file — which is where you want it, because by the time a recording exists the untruth is already recorded.

So keep the two failure classes apart; they have two different instruments. A leak into a tool — impurity, a live read, an effect performed where a value should have been returned — is caught at compile time, by a check. A leak into the record — the recording being insufficient to re-derive the run — is caught here, and only here. The second class is the one this page owns, and it is not hypothetical: if the fold read the clock instead of taking now off the record, the re-fold time-stamps differently and the states diverge (measured on this reference: live at:1001, re-folded at:0). If the boundary stamped the Signature without committing it, replay reconstructs the wrong authorship. If a block stood up a second bus, the re-fold is missing every write that went to it. If two folds were allowed to interleave (§ E), State is corrupted before it is ever compared.

That division of labour is not a weakness of the harness; it is the reason the enforcement gate below is a rung and not a nicety. One instrument proves the code cannot lie; the other proves the record cannot be incomplete. A book that claims one of them does both ends up, in practice, with neither — which is how this page came to describe a test that could not fail as the thing that proved every other seam held. It is still the outermost circle. It is just honest now about what it encircles.

E

More boundaries — advanced, optional

Three further seams, each an opt-in rung, not part of the core. The seven seams you have read are the architecture; these are what you add when the load demands it. Each gets the same four-line treatment — and each, note, exists in service of the same two instruments: the harness above, and the checks that guard what the harness cannot see. What has changed since this page was first written is that all three now ship: the gate has been failing builds for a while, and the relay and the mailbox are exercised code in both reference ports, with tests that go red when the behaviour is taken away. Read them as machinery, not as promises.

These are deliberately compact. Reach for them when a concrete pressure appears — a slow deep model, bursty input, generated code at volume — and not before; being real is not the same as being owed. None of them changes the rings; each one earns its place by protecting something the harness at the top of this page cannot protect for itself. And two of the three arrived the way any feature arrives, as blocks — a folder and a registration line — so an application that never tiers and never barges in registers neither and pays nothing for their existence.

Seam · the tiered relay
A slow deep tier and the fast tier communicate only through an append-only relay, which the fast tier reaches through one bounded tool that returns text — no method handle, no shared object, no synchronous request. The read is bounded (fifty milliseconds in the ports) and it degrades into a sealed outcome, not a nullable string: Fresh, LastKnown — stale, and it says so in its own type — and Empty, which is the genuinely different fact that the deep tier has not published yet. What crosses: one recalled snapshot per turn, staged as an ordered off-bus fixture and carried on the committed ToolResult, so a re-fold resolves the same entry and the same branch and never re-queries — and it carries no Authority, because a peer's conclusion is a suggestion, not an instruction. Why: two cognitive speeds where neither stalls the other, structurally rather than aspirationally — the party that must not block is the party that owns the bound. What breaks: shared mutable state between the tiers kills replay, and an uncaptured recall is quieter and worse — an asynchronously published relay lets a re-fold recall a different entry than the live run and call it agreement. The proof is a test that tampers with the committed record by swapping only the variant, same text and same timestamp, Fresh → LastKnown, and requires the golden trace to fail.
Seam · the barge-in mailbox
A serial consumer that selects over two things at once — the next message, and the running turn's completion (select in Kotlin, Promise.race in TypeScript) — which is the single property that makes a message observable while a turn runs, and therefore the property every policy below stands on. Three policies, one per message kind, each a closed choice rather than a flag: an Input is conflated on a perishable source — newest wins, and the drop is folded as a counted signed command that the winning turn's own context digest reads — or queued on a durable one, deduped on a source key and acked only after the commit; an Interrupt preempts, cancelling the in-flight turn and joining it under a deadline before the next one starts; a Drain defers, and never preempts. What crosses: one staged event at a time into a read-only ctx, plus the turn's single revocable channel back to the boundary. Why: bursty or interrupting input without dropping the single-writer guarantee — and cancellation lands at a step boundary, so a preempted turn's already-committed steps stay folded and their effects stay performed. There is no rollback and no compensating write. What breaks: concurrent folds corrupt State. When the bounded join expires the turn is abandoned rather than awaited: its channel is revoked, the blown deadline is folded as a fault, and the next turn starts anyway — because an unbounded join is precisely the hang the bound exists to prevent, and a turn that throws degrades to a typed outcome instead of killing the consumer.
Seam · the enforcement gate
The invariants compiled into blocking build checks: the stamp is minted only at the boundary, tools are pure, dependencies point inward, the fold cannot key an effect, no catch-all in a closed match. What crosses: nothing at runtime — it is a fence around the seams, run by the normal build. Why: § D. The harness cannot catch a tool that reaches for the world, because a re-fold never runs a tool; a check catches it at the line, at the moment it is written — which matters most exactly where the other seams are under most pressure, generated code at volume. The reference ports ship fifteen such checks, each with a violating fixture it must reject and a compliant one it must accept, wired into npm test and ./gradlew check; there is no warning tier. The newest is the one that turns a claim about the trunk into something the build owns: the spine may not name a block or the root — a tier-level denial that no per-folder allow-list can relax by accident, and the reason the spine can be lifted out whole. What breaks: without them the seams erode and nothing goes red — not the build, and not the harness.

Read those once for awareness, not mastery — but read them as descriptions of code. The point is still the asymmetry: the core seven seams are load-bearing and you cannot skip them; these three are rungs you climb only when a real pressure asks for them. What is no longer true is that they are sketches, and the difference is the kind you can check. Preemption is asserted against a measured control run — the identical turn with no interrupt is timed first, and takes ten seconds of virtual time; the interrupt's turn is then required to start inside the first two hundred milliseconds — and the same test file transcribes, inline, the drain loop the reference originally specified, and shows that it cannot do that, because outcome = await(inFlight) sits at loop-body indentation and control never returns to take() mid-turn. Replay of a recall is asserted against a tampered record — flip only the branch, Fresh to LastKnown, and the golden trace must go red. Both were verified the only way such tests can be: by breaking the consumer until they failed, and putting it back. Neither touches a wall clock; both run on virtual time, so the numbers are assertions rather than races.

And note that the third rung has moved. On the evidence of § D, the enforcement gate is not merely insurance for the harness at the top of this page; it is the only instrument that catches half of what the harness was once credited with catching. The two together are what let you say the whole session re-derives, exactly, from a recording alone — and mean it.

What the rungs do not buy — named here, not discovered later

Two honest limits, both written into the source rather than left for an adopter to find. The bounded join bounds the consumer, not the turn. A turn that ignores its cancellation signal may never unwind; what the deadline actually guarantees is that the next fold starts anyway and the abandoned turn can no longer reach the boundary, because the one channel it was given is revoked — the deadline becomes the step boundary. Closing the leak entirely would need an unbounded join, which is the hang. So it is named, degraded, counted and folded — never hidden. And single-writer confinement is structural, not checkable. The consumer mints the turn's only channel and calls the boundary itself, on its own single-threaded context, so two folds cannot interleave in the reference — but no build check enforces it, and an adopter who runs a turn on another thread can interleave two folds in spite of the design. That one is specified but unproven, and it is labelled that way in both ports rather than counted as parity it has not earned.

That closes the worked example. One command, traced through every seam; one impure boundary; one law — source dependencies point inward; one test that cashes them all, and one gate that keeps the test honest.
