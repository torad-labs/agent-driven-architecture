Seam 06 · Slices and wiring

Blocks and the root.

Two seams in one page. A block is a self-contained feature — a mini-hexagon, Clean Architecture's partial boundary — whose only public symbol is its tool registration. The composition root wireApp(env) is Main: the single place, in the whole program, where concrete adapters are chosen. A block contributes typed pieces up into one shared spine; the root passes concrete adapters down.

▸

The seam at a glance

The eight slots — but read as two seams that frame each other: the block (a bundle of seams behind one registration) and the root (the one dirty wiring place). Read these, then the deep-dive below.

The seam
A block: a vertical slice that bundles many seams behind a single public symbol — its tool registration. And the root: the one site, wireApp(env), where concrete adapters are chosen. The seam is the line a block draws around itself; the root is the line Main draws across all layers.
Each side
Inner: the spine — one bus, one fold, one boundary (the trunk). Outer / leaf: the block — a namespaced State slice, its one fold arm, its two projections, a port and its private adapter (the leaves). A block plugs into the trunk; it is never the trunk.
What crosses
Up (block → spine): a verb table, a State-slice shape, one fold arm, two pure projections, and its transport cases (ToolResult, Command, any Effect) — typed pieces, contributed into the shared spine. Down (root → block): concrete adapters, chosen once. Forbidden: a block importing a sibling's internals, or instantiating a second bus, fold, or boundary — a second baseplate.
Direction
A block depends only on shared domain types, the bus, and the folded State — never on a sibling, never outward at all. Only the root spans layers: it alone names HttpModel, LivePager, TicketQueue. Everything else points inward.
The inversion
Two blocks couple only through shared State and the bus — never by import. The escalation block reads “ticket #4118 is High” from the folded State the priority block wrote; it never reaches into the priority block to ask. State is the wire; import is forbidden.
Why it exists
A block is a partial boundary you can promote to a hard one later — a place held open for change at low cost. The root is the one deliberately dirty seam (Main), so that dirt is named and contained instead of smeared across every feature.
What breaks
A block that reaches into a sibling's slice by import couples them into one unit that can no longer move. A block that stands up its own bus creates a second mutation path — a write replay never sees. The check that dies: replayTest, because re-folding the committed records no longer reproduces what the live run believed.
The test
A block is tested in isolation against its contract: feed its verb, fold its arm, assert its slice, effects and notices — no siblings, no root, no live adapters. The root is exercised by the replay harness, which wires the whole graph, runs a live session, and re-derives it from the bus alone.
A

What a block is — a mini-hexagon behind one symbol

The seam pages so far have dissected the spine: one State and fold, one boundary, one bus. But a real application is not one feature — it is many, and they must be added, tested, and removed without each touching the others. The unit that makes that possible is the block: a self-contained feature, a mini-hexagon, whose entire public surface is a single symbol — its tool registration. Everything else it owns is private.

A block contributes a fixed set of typed pieces into the shared spine, and nothing more: a verb table (one row per tool — name, input schema, pure body, the signing entry, and its reversibility), a namespaced State slice it alone writes, one fold arm that translates its ToolResults into that slice, two pure projections of it (one for the screen, one for the reasoner's context), and its transport cases — a ToolResult and a Command per verb, plus any Effect it emits. When it reaches the world it also owns a port with a private adapter behind it. Siblings see none of that. They see one symbol: register.

Treat escalation as a block. Its verbs are requestEscalation and confirmEscalation; its slice is the per-ticket TicketStatus; its arm turns those two results into status transitions; and behind a private OncallPort sits the adapter that actually pages. It plugs into the same spine as setPriority — same bus, same fold, same boundary — and it knows nothing about the priority block at all. Eight files — the six every block carries, plus the port-and-adapter pair the pager needs — one export:

an escalation block — only its registration is public; everything else is private to the blockpseudocode
// ── BLOCK: escalation ─────────────────────────────────────────────
//   contract · slice · tools · fold · project · register  (+ port · adapter)
//   public surface = ONE symbol: register. Everything below it is private.

block Escalation {

  // (1) PUBLIC — the only export. Bundles everything below into one value.
  register(read: State -> EscalationSlice) -> BlockRegistration {
    verbs: [ requestEscalation, confirmEscalation ],   // the verb table
    arm:   escalationArm,                              // its ONE fold arm
    view:  escalationView,                             // slice → view rows
    lines: escalationContextLines,                     // slice → the reasoner's digest
    owns:  isEscalationResult }                        // which results are mine

  // (2) PRIVATE — the verb table. Pure bodies; NO actor, NO authority anywhere
  //     in this file — a ToolResult cannot even DECLARE one (seam 02).
  private requestEscalation = Reversible {
    name: "requestEscalation", schema: { ticket },
    run:  (input) -> RequestEscalation { ticket: input.ticket },
    sign: (result, sig, id) -> Command.RequestEscalation { sig, id, ticket: result.ticket } }

  private confirmEscalation = Irreversible {     // Irreversible CANNOT be constructed
    name: "confirmEscalation", schema: { ticket },   // without answering the next line:
    requestedBy: (state, r) -> read(state).statusOf(r.ticket).requestedBy,   // WHO asked
    run:  (input) -> ConfirmEscalation { ticket: input.ticket },
    sign: (result, sig, id) -> Command.ConfirmEscalation { sig, id, ticket: result.ticket } }

  // (3) PRIVATE — the ARM, over THIS block's slice only (seam 01). It reads its
  //     own state first, and the irreversible effect lives in the success branch.
  private escalationArm(slice, r, now, sig):
    match r.tool {
      "requestEscalation" -> slice.statusOf(r.ticket) is Open
          ? ArmOut(slice.withStatus(Escalating(r.ticket, sig.authority)), [], [])
          : ArmOut(slice, [], [ Notice.Rejected(now, r.tool, "not open") ])   // per item, not the banner
      "confirmEscalation" -> slice.statusOf(r.ticket).requestedBy != null
          ? ArmOut(slice.withStatus(Escalated(r.ticket, sig.authority)),
                   [ Effect.PageOncall(r.ticket, at = now) ], [])
          : ArmOut(slice, [], [ Notice.Rejected(now, r.tool, "no pending request") ])
    }
    // NOT here: who MAY confirm. The boundary already refused a self-confirm and
    // committed that verdict as ToolResult.Refused, before the fold ran (seam 02).

  // (4) PRIVATE — the block's port + its own adapter (seam 05). Siblings never see it.
  private PORT OncallPort { page(ticket) }
  private adapter LivePager implements OncallPort { ... }   // chosen by the ROOT, not here
}

Read what is and is not exported. Out of the block: one register value carrying a verb table, an arm, two projections and an ownership test — plus the transport cases the root unions in. Kept inside: the tool bodies, the arm's internals, the slice's transitions, the port, the adapter. A sibling cannot name escalationArm or OncallPort — they do not exist outside the block, and the build check that says so is not a review comment. That asymmetry is the partial boundary: a feature you can reason about, test, and later harden as a unit.

One absence in that listing is worth stopping on: nowhere does a verb ask who is calling. There is no ctx.actor to read — ctx carries exactly two members, state and context — and no ToolResult case has a field of type Actor, or can be given one. A verb able to name its own authorship is a verb able to forge it, so the answer is minted after it returns, at the boundary, and the confirm gate keys on the Authority recorded in Escalating(requestedBy) rather than on anything a block can see. The forgery was attempted against both reference ports — an Actor field added to the confirm result and populated inside the tool — and it does not compile in either. That is the difference between an invariant and a habit.

B

How blocks plug into one spine

A block never stands up its own infrastructure. It does not new Bus(), it does not write its own fold loop, it does not own a boundary. Those are the spine — one each, shared — and the block plugs into them through the typed pieces it registers. The priority block and the escalation block both contribute up into the same trunk; the root reaches down and hands the trunk its concrete adapters.

You can read all of that off the folder names, which is the point of arranging them this way. Here is the whole tree of the assembled program — trunk, leaves, root — with nothing elided:

Four placements carry the design, and none of them needs a comment to explain it. One: spine/pure/ beside spine/boundary/ is the purity line, drawn as a folder — every impure capability in the system lives on the right of it, plus one adapter file per block. Two: spine/ports/ holding only interfaces makes “a port is a published contract, not an implementation” a property of the directory rather than a convention someone remembers. Three: inside a block the same line is drawn again by file name — contract · slice · tools · fold · project are pure, adapter is the rim, and view-state is the ephemeral-only exception. Four: app/ is the single folder permitted to name every block at once. Those are checkable claims, and they were checked: spine/ imports a block in zero places, a block imports a sibling in zero places, and the only files in either port that import a block are the four in app/. The first of those is no longer only measured, either — a build check now denies the spine naming a block or the root at all, which is the difference between a trunk that happens to be tidy and one you can lift out whole.

The presentation block is worth a second look, because it is where an architecture usually cheats. console/ has the same six files as triage/: focusTicket and setPanel are verbs with the same shape, the same signing entry, the same commit path and the same cost as setPriority. There is no second tool mechanic and no “folds, does not sign” row anywhere in the tree — an agent that repositions the interface leaves the same auditable trail as an agent that changes a ticket, which is exactly why you would let it. What does not fold lives in one file, view-state: hover, scroll offset, unsubmitted text. The line is not UI-versus-domain; it is decision-versus-ephemeral.

The last two folders are the ones that test the model rather than illustrate it, because they were not planned with it. analysis/ and inbox/ arrived later, carrying the two advanced rungs of seam 07 § E — and they arrived as blocks, with the same file set — analysis adds the port-and-adapter pair, exactly as escalation does — the same one public symbol, and not one new line in the spine's fold, the boundary, or the bus. analysis/ is the tiered relay: two verbs, recallAnalysis for the fast tier and publishAnalysis for the deep one, plus a relay port with a private adapter behind it exactly as escalation has a pager. There is no “deep tier” module anywhere — the deep tier is a registration, because the block's register takes the tier as an argument over a closed set and the root decides which tier may publish and which may only recall. inbox/ is the barge-in ledger: noteDrop and noteFault, ordinary signed verbs, so a conflated input or a blown cancel deadline travels the same resolve → gate → fold → commit path as setPriority and lands on the same timeline. Six blocks, then, and the two hardest of them arrived without the trunk ever learning their names — which is the claim this whole page makes, finally made by features the page was not designed around. What they did need they took at the trunk's own tier and took once: a consumer, a mailbox port, a relay port, and the staged-input vocabulary both rungs share. An application that takes neither rung registers neither folder and is unaffected by both.

The slice is the heart of it. Each block owns a namespaced region of the one State — the whole value is a product of slices, one field per block — so the priority block writes state.triage, the escalation block writes state.escalation, and both key their own maps by ticket id without either being able to reach the other's. They share the same State value and the same fold loop, but their arms touch disjoint fields. So a block reads what a sibling produced the only honest way — off the folded State — and writes only its own region. The bus carries the signed commands; the State carries the result; neither block ever imports the other.

A block is a partial boundary — by design

Clean Architecture distinguishes a full boundary (a polymorphic interface with two implementations, fully decoupled) from a partial one (a slice you have isolated but not yet fully inverted). A block is the partial kind on purpose: it is held open at the seam — one public symbol, a private interior — so that if the feature earns it, you promote it to a hard boundary later. You do not pay for the full boundary up front. You pay for the line that lets you draw the full one cheaply when the day comes.

All of which is worth precisely what it costs to change something. So here is the bill, measured rather than asserted — each row was performed against both reference ports end to end and then reverted, counting every site the change actually touched. The table states the shape, which is architecture; the per-port counts are facts about a port and are stated, measured, with the exact command that recounts them, in each port’s own README — because the two ports pay in different currencies and averaging them would hide both:

Read the first row as the headline and the fourth as the honesty. A verb costs four appended declarations, and it costs the same four whether it changes a ticket or moves a panel — that uniformity is the whole argument for one tool mechanic, and it is why the presentation block has no discount and needs none. But a block does not plug in with one line, and no one should claim it does: the compiler and the build declarations together demand a couple of dozen edit sites spread over half a dozen files, because compile-time exhaustiveness is not free and a wall is not free either. The two ports do not pay the same bill, and that is the finding rather than an inconsistency — one writes every union membership out by hand and keeps the whole block inside its own package; the other closes its unions automatically and pays instead by authoring the block’s transport inside the shared core, so its four declarations for a verb live in one folder but two directories and two modules. Both counts are measured, per port, in the two READMEs, each beside the command that reproduces it; the honesty here is that neither is one line. Every site is an append to a closed set rather than an edit to shared logic, and every one is named for you rather than discovered later. That is the strongest form of “plug it in, pull it out” available under a type system that also promises you an edit list — and the trade is stated, not hidden.

The one site the compiler does not name — a real hole, in one of the two ports

TypeScript has a fifth site for a new verb, and it is silent. Each block exports an ownership test — isEscalationResult — whose declared type claims to narrow the block's whole result union while its body enumerates tool names by hand. Add a verb, declare all four sites correctly, forget that predicate: the typechecker exits 0, the linter exits 0, every test passes, and the verb then crashes at dispatch, because the root's fold falls through to a never that returns nothing. That was measured, not imagined. Kotlin does not have the hole — its root dispatch is a real sealed type check, so the compiler routes a new variant with no root edit at all. Where the two ports differ, say which one you are quoting: four sites, every one named for you, is the Kotlin number — paid for by authoring two of the four inside the shared core, because Kotlin seals a hierarchy within one module. TypeScript’s is five, all of them inside the block’s own package, and the fifth is the one you must remember.

C

The composition root — the one place adapters are chosen

If a block never names a concrete adapter, someone must. That someone is the composition root, wireApp(env) — this architecture's Main. It is the single function in the program that spans layers: it constructs the spine, picks each port's concrete implementation from the environment, and hands them down. Every new of an impure thing lives here and nowhere else.

the composition root — verbatim from the assembled program (seam 06)pseudocode
wireApp(env):
  bus      = Bus()
  ids      = SequentialIds()
  clock    = env.live ? SystemClock() : FixedClock(env.t0)
  authz    = env.live ? HostAuthority(env.session) : ScriptedAuthority(env.fixtures)
  model    = env.live ? HttpModel(env.url) : ScriptedModel(env.fixtures)   // ← the swap
  sink     = env.live ? LiveSinks(pager, store) : RecordingSink()
  sensing  = TicketQueue(env.queue)
  registry = register(triage) + register(escalation) + register(console)
           + register(artifact) + register(analysis) + register(inbox)     // one line per block
  boundary = Boundary(clock, ids, bus, sink, authz, registry, fold, projectContext)
  return App(boundary, sensing, model)

Eleven lines, and they are the only eleven allowed to be dirty. Notice what they do, in three movements. They bind every port to an adapter — Clock, IdSource, Bus, Sink, Authorization, ModelProvider, EventSource — including the swap, HttpModel live and ScriptedModel under test, at the one site a swap is legal. They register the blocks, one line each — and the escalation block's private OncallPort is satisfied right here, where LivePager meets it, because a block declares its port and the root alone decides what fills it. That list is also the allowlist: the analysis block registers as a tier, so it is this line — and nothing inside the block — that decides the fast tier may recall a peer's conclusion and may never publish one. Then they build the spine once, handing the boundary the six things it may not construct for itself — clock, ids, bus, sink, authority, registry — and the two total dispatchers it may not write.

That middle movement is the one G11 rests on. Plugging a feature in is its register(...) line here, its slice field in app/contract (plus, in TypeScript only, its three union memberships), its branch in each of app/assemble's dispatchers, and its appearance in the demo that exercises it — which is why the bill above counts four root files and not three. Pulling it out is the same list, subtracted, plus deleting the folder. It is not one line, but every entry is an append the compiler asks you for, and every entry is inside app/.

This is the whole reason the rest of the program can be pure. Push every construction decision to one function and the dependency arrows everywhere else point inward — toward interfaces and shared types — because nothing else is allowed to know a concrete name. The root is the sink for all the impurity that the seams quarantined: it spans layers so that nothing else has to.

D

What breaks without it

Two violations dissolve the block boundary, and both are tempting because they look like less work. The first reaches sideways; the second builds a second trunk.

Collapsed — the escalation block imports the priority block's internals

block Escalation {
  import Priority.priorityArm  // reaches into a sibling's interior
  run(input, ctx) -> if Priority.levelOf(ctx, input.ticket) == Urgent: ...
}

It compiles, and it even reads naturally. But the two blocks are now one unit: you cannot test escalation without dragging priority in, cannot move or delete either, and the “single public symbol” line is gone. The block was a partial boundary you could promote; now it is a knot you must first untie. The honest path was already available — read the level off the shared, folded State, which the priority block wrote there for exactly this. The test that dies: the block-in-isolation test — escalation can no longer be exercised against its contract alone, because its contract now secretly includes the priority block.

Collapsed — the block stands up its own bus (a second baseplate)

block Escalation {
  private bus2 = Bus()  // a second mutation path
  run(input, ctx) -> bus2.commit(ConfirmEscalation(input.ticket))
}

Now there are two append-only logs, and the truth is split across both. The replay harness reads the one recorded stream — the spine's bus — folds it, and gets a State that is missing every escalation the block committed to bus2. The test that dies: replayTest — refold(initial, bus.records()) no longer reproduces the state the live run actually held, because a second baseplate created a write the recording never saw. One bus is what makes the session a single replayable fact; a second bus deletes that guarantee.

Both failures share the spine's shape inverted: a capability that belongs to the one trunk — a sibling's interior, or the single bus — got duplicated or breached inside a leaf. The block boundary exists precisely so neither is writable by accident: a block can only reach a sibling through State, and can only commit through the spine it was handed.

E

The two tests the seam makes possible

The block and the root are tested at opposite scales, and that split is the payoff. A block is tested in isolation against its contract — feed its verb, fold its arm, assert its slice, the effects it emitted and the notices it raised — with no siblings, no root, and no live adapters in sight:

The confirm is gated — and the gate is not in the block

One fidelity point the block must honour: requestEscalation is agent-callable and reversible, but confirmEscalation fires the irreversible PageOncall, so it is gated. The gate is not in the tool and not in the arm. It runs at the boundary, before the fold commits, and it compares the confirming Authority against the one recorded in Escalating(requestedBy) — a different principal than the one that asked, which is the property that was wanted all along. Same principal, or no pending request: the action is refused, and the refusal is committed as a ToolResult.Refused, so it folds to a notice and a diagnostic and replays like any other decision. A different principal passes: the human host, a policy tier approving against rules, a second-agent reviewer, a deferred approval queue. In every one of those cases the Actor is stamped truthfully — a policy tier acting through the agent's stream is Agent — and it is the Authority that differs. That is what makes an unattended confirmer representable at all, and it is why the arm below never asks who is calling.

a block tested against its contract — no siblings, no root, no live adapterspseudocode
test "escalation block: an admitted confirm transitions to Escalated and pages once":
  pending = sliceWith(4118, Escalating(requestedBy = "agent-run-7f"))   // the agent had asked
  r       = confirmEscalation.run({ ticket: 4118 })         // pure; no ctx.actor to read
  out     = escalationArm(pending, r, now = t0, sig = Signature(Agent, "policy-tier-v3"))
  assert out.slice.statusOf(4118) == Escalated(confirmedBy: "policy-tier-v3")
  assert out.effects == [ Effect.PageOncall(4118, at = t0) ]   // its effect descriptor
  assert out.notices == []                                     // nothing to report

  // and the arm refuses what its OWN slice forbids — no request pending, no page:
  out2 = escalationArm(sliceWith(4118, Open), r, now = t0, sig)
  assert out2.effects == []                                    // the push lives in the success branch
  assert out2.notices == [ Notice.Rejected(t0, "confirmEscalation", "no pending request") ]
  assert out2.slice   == sliceWith(4118, Open)                 // and nothing moved

  // the self-confirm case is deliberately absent: it never reaches this arm.
  // The boundary refuses it first and commits ToolResult.Refused (seam 02).
  // no priority block, no bus, no wireApp — the block stands on its own contract

The root, by contrast, is the seam the replay harness exercises: it is the only thing that wires the whole graph, so it is verified by driving a whole session through it and then re-deriving that session from the records it committed. The two scales never overlap — a block proves its contract; the root proves the composition.

That is the same Clean-Architecture lesson the spine taught, applied one level up. There, one object was made impure so the rest could be pure. Here, one function — Main — is made cross-layer so every block can stay a single-symbol, inward-pointing slice. Concentrate the spanning in one named place, and everything around it gets small, testable, and free to move. A block is the vertical slice; wireApp(env) is Main; and keeping them honest is what lets the program grow feature by feature without the features fusing.
