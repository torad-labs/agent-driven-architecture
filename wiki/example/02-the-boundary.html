Seam 02 · The one impure object

The boundary adapter.

The single place the pure core touches the world — and the only object in the system allowed to be impure. It reads the clock, projects the context, resolves an open Action into a sealed ToolResult, stamps the Signature, gates the irreversible, mints identity, commits the step, and keys and performs the effects. Nothing else does any of those things.

▸

The seam at a glance

The eight slots, the same shape as every other seam. Read these, then the deep-dive below.

The seam
The membrane between the pure core and the impure world. Its job: turn a finished step — a list of open Actions — into resolved, gated, committed, signed, performed reality, in a fixed order.
Each side
Inner: the fold and State decide what is true; the registry's verbs and projectContext are pure and are called from here. Outer: the clock, the id source, the append-only bus, the authorization seam, the effect sinks. The boundary is the one thing that touches both.
What crosses
In: a FinishedStep — the staged input and a list of Actions: open (name, rawInput) pairs. It arrives on one of the boundary's three submission channels, and who acted is the channel's answer, never the step's. Out: one StepRecord to the bus, and KeyedEffects performed on the world. Forbidden: the fold never receives the clock, an id, or a live sink; a verb never performs an effect; nothing upstream of the stamp may name an Actor.
Direction
Source dependency points inward — the boundary names the fold; the fold names nothing out here. Control flows outward — the boundary drives the world only after the fold has decided and the bus has accepted.
The inversion
The fold returns Effect descriptors (plain data, unkeyed); the boundary is the adapter that keys them from the committed index and knows how to perform them. The core reaches the world through data it returns, never through a reference to a sink it holds.
Why it exists
To confine all impurity — clock, identity, the stamp, authority, commit, effects — to one auditable place, so everything else is pure and a live session re-derives exactly from its own committed bytes.
What breaks
Mint an id, read the clock, or perform an effect anywhere else and the re-fold stops matching the live run — replayTest diverges. Let anything upstream carry an Actor and authorship becomes forgeable at its source.
The test
The boundary is the one object you test with doubles: a fake clock, a fake id-sequence, a scripted authority, a recording sink — then assert the order gate → fold → commit → perform, and that a refused action committed a Refused result and fired nothing. Everything else is pure and needs none.
A

What it is

When a step finishes, the runtime hands the boundary one thing: a FinishedStep — what was staged for the turn, and a list of Actions. It does not say who acted: that is decided by which of the boundary's three channels the step arrived on, and a caller holds one. An Action is deliberately weak: a tool name and a raw input, both open, both possibly nonsense. It is the only open input in the system, and this is the seam that closes it. The boundary turns that into reality, in a fixed order, and this is the whole of it:

the one impure seam — verbatim from the assembled programpseudocode
boundary.<channel>(step: FinishedStep):                  // human | agent | spine
  by      = the channel's own Actor                        // (0) NOT a field of the step
  now     = clock.now()                                    // (1) the ONLY clock read in the system (G9)
  ctx     = Ctx(state, projectContext(state, step.staged, bounds)) // (2) the third pure projection
  results = step.actions.map(a -> resolveAction(registry, a, ctx))   // (3) the ONE name → ToolResult map
  sig     = Signature(by = by,                             // (4) the stamp — WHO, and under whose permission
                      authority = authz.authorityOf(by, session))
  gated   = results.map(r -> gate(r, sig, state, registry, authz))   // (5) PRE-FOLD, so the verdict commits
  (s, fx) = fold(state, gated, now, sig)                   // (6) pure call — decide
  index   = append(bus, StepRecord {                       // (7) COMMIT the step, not the pair
              schemaVersion, now, sig,                     //     the envelope rides the record (14.7)
              staged: step.staged, actions: step.actions, results: gated,
              commands: gated.map(r -> sign(registry, r, sig, nextId())),   // EVERY verb signs
              context:  ContextFixture(promptVersion, render(ctx.context)) })
  state   = s                                              // (8) adopt the new truth
  for (i, f) in fx:                                        // (9) the only place effects run —
    perform(KeyedEffect(EffectKey(index, i), f), mode = LIVE)   //     keyed from the COMMITTED index

Nine steps, and every impure capability in the system is in them: the clock (1), the stamp and the authority lookup (4), the gate (5), identity and the commit (7), and effects (9). Steps (2), (3) and (6) are calls into pure code — projectContext, the registry's verbs, and the fold — none of which touches any of those things. The boundary is the adapter; the fold is the policy.

The order is not a style choice; three of the pairings are load-bearing. The results are produced at (3), before the signature exists at (4) — so nothing downstream can learn who acted except through sig, and there is exactly one such value per step rather than two that might disagree. The gate runs at (5), before the fold at (6) and before the commit at (7) — so what gets committed is already the verdict, and a re-fold reproduces the refusal without calling the authorization seam a second time. And the effect key at (9) is built from the index that (7) returned — so step (9) cannot run before step (7) has, not by convention but because the value it needs does not exist yet.

B

What crosses it — and the rule that makes a human override free

Two data structures leave the boundary, and both are plain data — never an entity, never a live handle. Outbound to the bus: one StepRecord, carrying the signed Commands. Outbound to the world: KeyedEffects, performed. The Command is where identity and authorship are minted:

the stamp and the signed action — what crosses to the buspseudocode
enum Actor    { Human, Agent, Spine }           // WHO acted — grows only at architecture revision
value Authority(id: Text)                       // UNDER WHOSE permission — an opaque principal, not a variant set
value Signature(by: Actor, authority: Authority)             // minted at the boundary, and nowhere else — one
                                                             // production site in the app: a stamp a tool or a fold
                                                             // conjures for itself is a forged stamp (book 5.3)
sealed Command(tool: ToolName, sig: Signature, id: CmdId) {  // the parent declares all three
  SetPriority(ticket: TicketId, level: Priority)
  RequestEscalation(ticket: TicketId)                 // a request — reversible
  ConfirmEscalation(ticket: TicketId)                 // irreversible — gated at the boundary, on AUTHORITY
  FocusTicket(ticket: TicketId)                       // presentation — an authored act, so it signs
  SetPanel(panel: PanelId, visible: Bool)             // presentation — likewise
  Unhandled(note: Text) | Refused(reason: Text)       // a refusal is a decision; it signs too
}

The stamp is minted here — and, more to the point, it is unrepresentable anywhere else. That distinction is the difference between a convention and a mechanism, and only the second one holds. Look back at line (3): the results are produced before line (4) has minted a signature, and no ToolResult case and no Ctx field has a type that could hold an Actor or an Authority in the first place. So a verb cannot report who is asking — not because it has been asked not to, but because there is no field to write it into and no value in scope to copy. There is exactly one authorship value per step, it is created after the work has been described, and everything downstream reads it from the same place.

This is what makes the architecture's headline move real: a human tap and an agent tool-call both arrive as an Action, both enter at this one call, and both become a Command here — identical but for the Signature. They flow through the same gate, the same fold, the same bus, the same replay path. Letting a human do what the agent does is therefore not new code; it is the same action with a different stamp. In A Typical Scenario, swap step 4's by = Agent for by = Human and every other field of the committed record is byte-for-byte identical.

Two questions, two fields — and the gate reads the second one

Actor answers who acted. It is a closed set — Human, Agent, Spine — that grows only at an architecture revision, never per application; that fixed contract is why the surface and the loop can both be described in one sentence. Authority answers under whose permission, and it is an opaque principal id resolved at line (4) through the authorization port — a seam the product owns, not the architecture. The two come apart exactly where it matters. An agent re-confirming its own escalation is truthfully by = Agent with the same authority that raised the request, and the gate refuses it. A policy tier approving that same escalation against rules is also truthfully by = Agent — it acted through the agent's stream, and a confirming Command always stamps its Actor honestly — but its authority is a different principal, so the gate grants it. Keying the gate on the Actor would collapse those two into one; keying it on the Authority is what makes an unattended promotion representable without a human in the room, and without a second bus.

The bus the record lands on is append-only and observable — a committed, replayable log. “Commit” at line (7) means exactly this: the whole step — now, the signature, the staged input, what was asked, what was folded, the signed commands, and the digest of the context the reasoner saw — is durably appended before any effect fires at line (9). Committing the step rather than the pair is what makes the record re-foldable: drop now from it and a re-fold reproduces the decisions but not the timestamps, which is a recording that agrees with the run about everything except when it happened.

C

Why exactly one impure seam

Clean Architecture puts impurity all around its outer ring: the controller talks to the web, the presenter to the screen, the gateway to the database. Each is a separate place where the world leaks in. This architecture makes a sharper promise: collapse every one of those into a single object, and make it the only impure object in the system.

The payoff is that purity becomes a property you can state in one sentence and check at one place. Identity and time — the two things most likely to make a program non-reproducible — are injected into the boundary (the clock is read at line 1, ids are minted at line 7) and passed into the fold as ordinary values. The fold cannot reach for a clock or a random id because it was never handed the means to. That single discipline is what lets a live session re-derive exactly from the step records it committed.

The order is the contract

Read lines (7)→(8)→(9) again: commit, then adopt, then perform. If a crash happens between commit and perform, recovery re-reads the committed records, re-folds to the same state, and re-issues the same effects — which the sinks dedupe on KeyedEffect.key. That key is EffectKey(committed step index, position within the step): derived, deterministic, and identical on every pass, which is what makes a retry idempotent rather than a second page at 3 a.m.

Notice where the key is not. It is not a field on Effect, so the fold has nothing to mint it into — and could not mint it correctly anyway, since the index it is built from does not exist until append has returned. The wrapper is what makes the ordering structural: perform accepts only a KeyedEffect, a KeyedEffect needs an index, and an index only comes from a completed commit. The boundary's job is not just to be the one impure place; it is to be impure in an order the type system will not let you scramble.

D

What breaks without it

The seam earns its keep only against the version that omits it. Here is the most tempting violation — a tool that just does the work itself:

Collapsed — the tool performs the effect

VERB setPriority = Reversible {
  run(input, ctx) -> { db.write(input); pager.page(input) }  // impure!
}

It looks shorter and it works on the happy path. But the tool now performs an effect, so it is no longer a pure function of its input. The test that dies: replayTest can no longer run off-target — the harness is supposed to re-derive a live run from committed bytes alone, and this tool reaches the world every time it is asked anything, double-writing and re-paging on each pass. You have not saved code; you have deleted replay.

Collapsed — something upstream carries the actor

The tempting version is not a lying surface; it is a helpful one. Give the verb's context an actor field so a tool can “record who confirmed”, let the result carry it as by: Actor, and gate on that field in the fold. Every step of that looks reasonable, and the result is two authorship values per step that nothing reconciles: the one the tool copied, and the one the boundary stamps a line later. The gate reads the first; the audit log records the second. When they disagree — and a bad inference or an injected instruction is all it takes — the log says the agent did it while the gate was told a host had, so the audit is truthful about a decision that was made on a forged premise. What dies is not a test. Replay stays green, because replay faithfully re-folds the forged value. What dies is the meaning of the record.

The fix is not vigilance, it is arithmetic on the order of lines. The results exist at (3); the signature does not exist until (4). If nothing upstream of (4) has a field of type Actor, Authority or Signature, then the second value cannot be constructed, and there is only ever one. Then move the gate to where the one value lives — line (5), at the boundary, before the fold — and key it on the Authority, comparing the confirming principal against the requesting principal the state already recorded. An agent acting through its own step is stamped with its own run's authority and is refused by that comparison, not by a rule about the word “Human”. That is a mechanism. “The tool should copy the right actor” is a hope.

Both failures share a shape: a capability or a fact that belongs to the boundary appeared somewhere upstream of it, where it can be neither audited nor reconciled. The seam exists precisely to make that unwritable rather than merely discouraged — the first by giving pure code no sink to reach, the second by giving it no field to fill.

E

The test that the seam makes possible

Because the boundary is the only impure object, it is also the only one you ever test with doubles. Inject a fake clock, a fake id-sequence, a scripted authority and a recording sink, then assert the order of what came out — and, separately, what a refused action leaves behind:

testing the one impure objectpseudocode
test "commit precedes perform, and the effect key comes from the committed index":
  clock = FakeClock(t0); ids = FakeIds([c1]); sink = RecordingSink()
  authz = ScriptedAuthority(Agent -> "agent-run-7f")
  boundary.agent(FinishedStep(staged = [],
    actions = [ Action("setPriority", { ticket: 4118, level: "High" }) ]))
  assert sink.log == [
    Append(StepRecord(schemaVersion = 2,                            // the envelope (14.7)
                      now = t0, sig = Signature(Agent, "agent-run-7f"),
                      actions  = [ Action("setPriority", …) ],       // what was ASKED
                      results  = [ SetPriority(4118, High) ],        // what was FOLDED
                      commands = [ Command.SetPriority(sig, id = c1, 4118, High) ])),
    Perform(KeyedEffect(EffectKey(step = 0, index = 0),              // commit BEFORE perform —
                        Effect.LogDecision(at = t0, 4118, High)))    //   and the key proves it
  ]

test "an agent cannot confirm its own escalation":
  drive(requestEscalation(4118), by = Agent, authority = "agent-run-7f")
  drive(confirmEscalation(4118), by = Agent, authority = "agent-run-7f")   // same principal
  assert bus.last().results.last() is ToolResult.Refused                   // the verdict is COMMITTED
  assert bus.last().commands.last().sig.by == Actor.Agent                  // stamped truthfully anyway
  assert sink.performed.none(it.effect is Effect.PageOncall)               // nothing fired
  assert state.statusOf(4118) is Escalating                                // and nothing moved

test "a different authority may":
  drive(confirmEscalation(4118), by = Agent, authority = "policy-tier-v3") // unattended, no human
  assert sink.performed.any(it.effect is Effect.PageOncall)

The first test pins the order, and it pins it with evidence rather than with a comment: EffectKey(step = 0, …) is a number that only exists because the append returned it, so an implementation that performed first could not produce this log at all. It also shows why the record carries both actions and results — here they agree, and in the second test they do not.

The last two are the gate, and they are the reason the boundary is worth testing carefully. Nothing about the refusal is a special case: it is a ToolResult.Refused that gets folded, signed and committed like any other decision, so the audit answers “why did nobody get paged?” from the record instead of from a missing entry. And nothing about the grant requires a person — the third test promotes an escalation with no human in the room, because the comparison the gate makes is between principals, not between an actor and the word Human.

Everything else in the program — the fold, the verbs, the projection — is pure and is tested by direct call, with no doubles at all. That asymmetry is the whole point: one object is hard to test, so it is made small and tested carefully; everything else is made pure, so it is trivial to test. That is the Humble Object pattern, and the boundary adapter is its sharpest instance in this architecture.
