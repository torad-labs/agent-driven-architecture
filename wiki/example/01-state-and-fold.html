Seam 01 · The inner ring

State and the fold.

The centre of the diagram, and the seam everything else is built to protect. The State is the enterprise truth — a product of slices, and every closed set inside it a sealed union. The fold is the pure reducer fold(state, results, now, sig) that turns gated tool results into a new immutable State plus Effect descriptors. It reads no clock, mints no id, keys no effect, performs no I/O — which is exactly why the whole session replays.

▸

The seam at a glance

The eight slots, the same shape as every other seam. Read these, then the deep-dive below. This page covers three tightly-bound seams — State, the fold, and Effect — with the fold as the primary one: State is its in and out, effects are what it emits.

The seam
The pure reducer fold(state, results, now, sig) -> (newState, effects) — the use-case layer. It folds gated ToolResults into a new immutable State and a list of Effect descriptors. Nothing else decides what is true.
Each side
Inner: State, Ticket, TicketStatus — the entities, the enterprise truth; a product of slices with a sealed union at every closed set. Through it: the fold reads the current State and the results, and produces the next State. The fold imports nothing foreign; the entities import nothing at all.
What crosses
In: the current state, a list of ToolResult the boundary has already gated, now — a clock reading passed as an ordinary value — and sig, the stamp minted one line earlier. Out: a new immutable State and a list of Effect descriptors (plain data). Forbidden: the fold never reads a clock, never mints an id, never keys an effect, never performs one, never does I/O. now and sig are handed in; effects go out as data, unkeyed.
Direction
Source dependency points inward — the fold names State and the entities, and nothing outer; the entities name nothing. Control flows outward — the fold returns Effect descriptors that the boundary will later key and perform.
The inversion
The fold emits Effect descriptors — plain data — instead of performing the effect. That is the Output Port: the core reaches the world through data it returns, never through a sink it holds. The boundary is the adapter that keys and performs them.
Why it exists
Purity. Because the fold is a pure function of (state, results, now, sig), the committed step records re-fold to a bit-identical state every time — the whole session replays — and the fold is tested by a direct call, with no doubles.
What breaks
Let the fold read the clock or perform an effect and the re-fold stops matching the live run it is supposed to reproduce — replayTest's live-vs-replay comparison goes red, and the second pass double-writes the world on its way there. You have not saved a line; you have deleted replay.
The test
Call it and assert the values: the transition happened, the effect list is exactly the descriptors you expect, and the world is untouched. Then call it on a state the transition is invalid against and assert the opposite — no mutation, no effect, one Notice.Rejected, banner still ok.
A

What it is

At the centre of the rings sits the State — the Clean-Architecture Entities: the enterprise truth, the data and rules that would still be true if there were no agent, no screen, no network. State itself has exactly one shape, so it is a product of slices; but every closed set inside it is a sealed union, not a bag of flags, so that an illegal state cannot be named in the first place. A ticket is Open or Escalating or Escalated or Resolved — never two at once, never none.

the entities — verbatim from the assembled programpseudocode
enum Priority { Low, Normal, High, Urgent }
enum Actor    { Human, Agent }                  // WHO acted — two values; the contract never grows
value Authority(id: Text)                       // UNDER WHOSE permission — an opaque principal, not a variant set
sealed TicketStatus(ticket: TicketId) {
  Open | Escalating(requestedBy: Authority) | Escalated(confirmedBy: Authority) | Resolved
}
type  Ticket = { id: TicketId, body: Text, priority: Priority, status: TicketStatus }
sealed Notice(at: Timestamp, tool: ToolName, reason: Text) { Rejected | Refused }  // PER-ITEM
sealed RunStatus { Idle | Working(step) | Degraded(cause) | Error(fault) }         // SESSION-GLOBAL, boundary-only
type  State = { tickets: Map<TicketId, Ticket>,   // triage + escalation
                focused: TicketId?,               // console — a folded presentation decision
                panels:  Map<PanelId, Bool>,      // console
                run:     RunStatus,               // spine — the boundary writes this, no arm does
                notices: [Notice] }               // spine — one entry per rejection or refusal

Two of those declarations are doing more work than they look. TicketStatus carries an Authority on both of its live states: the ticket remembers which principal asked and, later, which principal confirmed — because “a different actor than the one who requested” is a comparison, and a comparison needs both sides recorded. And the split between Notice and RunStatus is the difference between this item failed and this session is unwell. One bad ticket writes a Notice; only the boundary ever writes RunStatus.

Around that truth runs the fold — the Clean-Architecture Use-Case Interactor, expressed as a pure reducer. When a step finishes, the gated ToolResult payloads are handed to the fold together with the current state, a single clock reading now, and the sig the boundary just stamped. The fold matches each result against the sealed set and returns the next truth plus the effects that truth implies — and this is the whole of it:

the pure reducer — the use-case layer, verbatimpseudocode
fold(state, results, now, sig) -> (State, [Effect]):
  for r in results:
    match r:
      SetPriority(tool, ticket, level) ->
        state.tickets.has(ticket)
          ? ( state.withPriority(ticket, level),
              [ Effect.LogDecision(at = now, ticket, level, supersedes = state.priorityOf(ticket)) ] )
          : ( state.withNotice(Notice.Rejected(now, tool, "unknown ticket")), [] )  // refused: no change, NO effect
      RequestEscalation(tool, ticket) ->
        state.statusOf(ticket) is Open
          ? ( state.withStatus(ticket, Escalating(requestedBy = sig.authority)),
              [] )                              // a request commits no irreversible effect
          : ( state.withNotice(Notice.Rejected(now, tool, "not open")), [] )
      ConfirmEscalation(tool, ticket) ->        // the gate already ran, at the boundary — step (5)
        state.statusOf(ticket) is Escalating
          ? ( state.withStatus(ticket, Escalated(confirmedBy = sig.authority)),
              [ Effect.PageOncall(at = now, ticket) ] )
          : ( state.withNotice(Notice.Rejected(now, tool, "no pending request")), [] )
      FocusTicket(tool, ticket) ->              // a PRESENTATION verb — folded like any other
        state.tickets.has(ticket)
          ? ( state.withFocus(ticket), [] )
          : ( state.withNotice(Notice.Rejected(now, tool, "unknown ticket")), [] )
      SetPanel(tool, panel, visible) ->
        ( state.withPanel(panel, visible), [] )
      Refused(tool, reason) ->                  // the gate's verdict, committed — so it re-folds
        ( state.withNotice(Notice.Refused(now, tool, reason)), [ Effect.Diag(at = now, reason) ] )
      Unhandled(tool, note) ->
        ( state.withNotice(Notice.Rejected(now, tool, note)), [ Effect.Diag(at = now, note) ] )

Read the arms as policy, not plumbing, and read them in pairs. Every arm asks the current state a question before it writes. SetPriority writes the new priority and asks for a log line stamped at = now — but only if the ticket exists; if it does not, the state is unchanged, the effect list is empty, and a Notice.Rejected is folded against that one item. The refused branch cannot leak an effect, because there is no effect in it to leak. RequestEscalation moves an open ticket to Escalating and records which authority asked, returning no effect at all — a request is reversible, so nothing irreversible may fire. ConfirmEscalation is the only arm that returns Effect.PageOncall, and it fires only when the transition it is asking for is actually available: a confirm against a ticket with no pending request pages nobody. FocusTicket and SetPanel are presentation verbs and get no special treatment — same arm shape, same validation, same commit path. And the two spine arms, Refused and Unhandled, are how a denial becomes part of the record instead of an absence in it.

No else arm — and that is the point

There is nothing to catch here, because there is nothing left uncaught. An open name — a tool the model invented, an input that failed to decode — never reaches the fold as a mystery; the boundary resolves it to Unhandled at the seam where the open name actually arrives, and the gate resolves a denial to Refused in the same place. By the time the fold runs, the set is genuinely closed, so the match can be total. That is what buys the compile-time edit list: add a fifth TicketStatus and the build breaks at the fold arm, at the view projection and at the context projection — three named sites, not a silent fall-through into a catch-all.

The gate itself is not here, and that placement is deliberate. Whether a confirming authority is allowed to confirm is settled at the boundary, one line before the fold is called, and its verdict arrives as a Refused result the fold simply folds. So the fold never asks who is acting, only what is true. Both clock-stamps — at = now — use the value that was handed in; the fold never reaches for a clock of its own, and it never mints an identity for the effects it returns.

B

What crosses it — effects as descriptors, not actions

The fold's output is a tuple: (newState, effects). The first element is the next enterprise truth — a fresh immutable State, never a mutation of the old one. The second is a list of Effect values, and these are the crossing that makes the whole architecture work:

effect descriptors — plain data the fold returnspseudocode
sealed Effect(at: Timestamp) { LogDecision(...) | PageOncall(...) | Diag(note) }

An Effect is a description of a thing to do, not the doing of it. Effect.PageOncall(at = now, ticket) is a small value that says “page on-call about this ticket”; it does not open a connection, it does not ring a phone. The fold returns it and is finished. Later, at exactly one seam — the boundary adapter — that value is matched and performed against the world. This is the Output Port of Clean Architecture, realised as data: the inner ring reaches outward by returning a description, never by holding a reference to the sink that will act.

Note what the parent declares, and what it conspicuously does not. It declares at, so every effect in the system carries a timestamp by construction — you cannot forget one, because there is no variant that could be missing it. It declares no identity. An Effect has no id, no key, no sequence number, and that absence is load-bearing: retry-safety at the far end depends on an idempotency key, and if the key were a field on Effect then the fold would be the thing that mints it — and the fold has no committed position to mint it from. So the key is not here. The boundary wraps each returned effect in a KeyedEffect derived from the committed step index, and the sink accepts nothing else. The fold cannot get the key wrong because it has no field to write it into.

Why data and not an action? Because data can be recorded, compared, and replayed; an action cannot. An Effect.LogDecision in a golden file is a fact you can assert against. A call to logger.write(...) buried inside the fold is a side effect you can only observe by spying. The architecture chooses the version you can hold still and look at — and that choice is the line between a session that replays and one that merely ran once.

Returns out, never reaches out

Trace the arrows. The current state and the results come in as arguments; the new State and the Effect list go out as the return value. At no point does the fold hold a handle to a database, a clock, or a sink. Control will flow outward — those effects do reach the world — but the source dependency points inward: the fold names State and Effect, both of which live in the inner ring, and names nothing in the outer ring at all.

C

Why pure — entities stable, now injected, illegal states unrepresentable

Purity here is not an aesthetic; it is three concrete disciplines, each buying a concrete property.

The entities are stable. State, Ticket, and Priority are the highest-level, least-volatile policy in the system — the part that changes only when the business changes, never when a framework or a screen does. Clean Architecture puts exactly this at the centre and forbids it from depending on anything outer. The fold sits one ring out and depends only on it. Nothing here knows that tickets arrive over a queue or that effects end up on a pager; that knowledge lives in rings the fold cannot see.

now is injected, not read. Time and identity are the two things most likely to make a program irreproducible, so neither is available to the fold. The clock is read once, far outside, and its value travels in as the ordinary argument now; both clock-stamps in the body — at = now — use that argument. The fold cannot reach for the wall clock because it was never handed the means to. The same goes for identity, twice over: it does not mint the CommandIds (the boundary does, at commit) and it does not mint the effect keys (the boundary does, from the committed index). Pass the same t0 and sig twice and the two folds are indistinguishable, byte for byte.

The unions make illegal states unrepresentable — and illegal matches unwritable. Two closed sets are doing that work. TicketStatus closes the truth: a ticket is exactly one status, so there is no “escalated and open” to guard against, because the type cannot spell it. ToolResult closes the input: every case the fold could receive is declared, including the boundary's own Unhandled and Refused, so the match is exhaustive with nothing left over and no else to hide in. The fold's correctness is therefore a property the compiler checks, not a set of runtime ifs the reader must trust — and when the truth grows a case, the compiler hands you the edit list instead of letting a catch-all swallow it.

The payoff, in one sentence

Stable entities + injected now and sig + an exhaustive match means the fold is a mathematical function of its arguments. Same inputs, same outputs, forever. That equality is not itself an interesting assertion — a pure function agrees with itself by definition — but it is precisely the precondition that lets seam 07 do something that is interesting: take a live run, re-fold nothing but the bytes it committed, and demand back the same State and the same effect sequence, timestamps included. Purity is not a virtue the fold has; it is the mechanism replay is built on.

D

What breaks without it

The seam earns its keep only against the version that omits it. Here is the most tempting violation — a fold that, instead of returning a descriptor, just does the work and reads the clock itself:

Collapsed — the fold performs the effect and reads the clock

fold(state, results) {  // note: no `now` argument
  for r in results: match r {
    SetPriority(tool, ticket, level) -> {
      db.write(ticket, level); logger.log("priority", ticket, level, at = now())  // impure!
      state = state.withPriority(ticket, level)
    } } }
}

It looks shorter and it works on the happy path. But the fold now reads now() and calls db.write and logger.log, so it is no longer a pure function of its arguments. The test that dies: replayTest. Its assertion is take a live run and re-fold only the bytes it committed; demand the same state and the same effect sequence — and the re-fold now reads a different now(), so every timestamp diverges from the run it is supposed to reproduce. Worse, it re-hits db and logger on the way, double-writing the row and re-logging the line: the harness that was meant to run off-target with no world at all now mutates the world every time you invoke it. You have not saved a line of code; you have deleted replay, and with it every off-target test the architecture promised.

Collapsed — the arm writes first and validates never

SetPriority(tool, ticket, level) ->
  ( state.withPriority(ticket, level),  // never asks whether the ticket exists
    [ Effect.LogDecision(at = now, ticket, level) ] )  // fires regardless

This one is quieter than the first and worse to live with, because nothing goes red. Set the priority of a ticket that does not exist and the map write is a no-op, so the folded State is unchanged — but the effect fired and the Command was committed. You are left with a clean-looking audit record for a mutation that never happened: the log says the priority changed, the state says it did not, and a re-fold agrees with the state, so replay is green. What dies is not a test, it is the record's meaning. The rule that prevents it is mechanical and has no exceptions — every arm reads current state before it decides, and every effect push lives inside the success branch — and its companion rule keeps the damage local: a rejection folds a per-item Notice.Rejected, never RunStatus.Degraded. Hijacking the session status for one bad ticket leaves the banner unwell for the rest of the session, because no later arm knows to clear it.

The failures share a shape: a capability or a decision that belongs somewhere else — reading the clock, touching a sink, waving through a transition the state does not permit — landed in an arm, where it can be neither passed in deterministically nor replayed nor confined to the item it concerns. The seam exists precisely to make those impossible to write by accident: the fold's signature has nowhere to reach a clock from, its return type carries effects out as data, and the arm's shape puts the effect inside the branch that earned it.

E

The test the seam makes possible

Because the fold is pure, it is the easiest thing in the program to test: a direct call, no doubles, no fakes, no setup. What you assert is the answer — the values that came back — and, just as loudly, the answer on the path where the transition is refused:

testing the pure reducer — direct call, no doublespseudocode
sig = Signature(by = Agent, authority = "agent-run-7f")

test "the arm transitions, and returns its effect rather than performing it":
  results = [ SetPriority(tool = setPriority, ticket = 4118, level = High) ]
  (s, fx) = fold(oneOpenTicket(4118, priority = Normal), results, now = t0, sig)
  assert s.tickets[4118].priority == High                   // the transition happened
  assert fx == [ Effect.LogDecision(at = t0, 4118, High, supersedes = Normal) ]  // RETURNED, as data
  assert world.untouched()                                  // nothing performed: no db write, no page

test "a refused transition writes nothing, fires nothing, and stays local":
  (s, fx) = fold(emptyState, results, now = t0, sig)        // ticket 4118 does not exist
  assert s.tickets == {}                                    // no mutation …
  assert fx        == []                                    // … and NO effect — the audit cannot lie
  assert s.notices == [ Notice.Rejected(t0, setPriority, "unknown ticket") ]     // per item
  assert s.run     == Idle                                  // the session is NOT degraded

Three things are proven and none of them needs a test double. First, the arm decides by reading state: the same result folded against two different states produces two different answers, and the second one is a refusal. Second, effects are returned, not performed — fx is a list of plain Effect values you assert against directly, the world is untouched because the fold has no means to touch it, and on the refused path the list is empty, so there is no way for the record to claim a change that did not happen. Third, a failure is per-item: it lands in notices, and run is still Idle, so one bad ticket does not leave the banner unwell for the rest of the session.

Notice what is not asserted here: that folding the same input twice gives the same answer. It does, but that is true of any pure function by definition and it catches nothing. The assertion that earns its keep lives at seam 07, where a live run is compared against a re-fold of its own committed bytes — an equality that can genuinely fail, and does the moment any of this page's discipline is broken.

That is the asymmetry the architecture is built on, seen from the inside. The one impure object — the boundary — is tested with fakes and is kept small. Everything in the inner and middle rings — the fold here, the tools, the projection — is pure, and is tested by direct call. State is the truth; the fold is the only thing allowed to change it; and because the fold is pure, the whole session of changes replays. Every later seam exists to keep that sentence true.
